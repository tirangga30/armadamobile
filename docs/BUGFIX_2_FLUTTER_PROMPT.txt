BUG 2 — "Terima Tugas" reverts after refresh (root cause: wrong HTTP endpoint)
===============================================================================

FILE: lib/data/repositories/armada_api_service.dart (around line 291)

CURRENT (broken):
```dart
Future<void> updateDeliveryStatus(String id, String status) async {
  try {
    await _client.post('deliveries/$id/$status');
  } catch (e) {
    debugPrint('Notice updating delivery status: $e');
  }
}
```
It posts `deliveries/<id>/ACCEPTED`, but the backend only exposes:
`POST /deliveries/:id/accept`, `/start`, `/complete`, `/cancel`.
The request 404s, the exception is swallowed, local state changes optimistically, then the
next refresh restores the server value.

REQUIRED:
1. Replace the method body with an explicit status → action mapping and return `Future<bool>`
   (true = server accepted the transition):

```dart
Future<bool> updateDeliveryStatus(String id, String status) async {
  final action = switch (status) {
    'ACCEPTED' => 'accept',
    'EN_ROUTE' => 'start',
    'DELIVERED' || 'COMPLETED' => 'complete',
    'CANCELLED' => 'cancel',
    _ => null,
  };
  if (action == null) {
    debugPrint('updateDeliveryStatus: unsupported status "$status" for delivery $id');
    return false;
  }
  try {
    await _client.post('deliveries/$id/$action');
    return true;
  } catch (e) {
    debugPrint('updateDeliveryStatus failed ($status → $action): $e');
    return false;
  }
}
```

2. Check every other call site of `updateDeliveryStatus` in the project with grep and make
   them still compile (a `Future<bool>` can be awaited and ignored, so most call sites are
   fine — only fix real compile errors).
