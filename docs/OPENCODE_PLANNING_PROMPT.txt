RUANG LINGKUP PERENCANAAN DETAIL (4 FASE BESAR):
1. FASE 1: Driver Granular Stop Execution & Physical Proof of Delivery (POD)
   - Per-stop state transitions: DEPART -> ARRIVE -> UNLOAD -> POD / DELIVERED, serta failure path FAIL (pilihan alasan gagal: TOKO_TUTUP, PENERIMA_TIDAK_DAPAT_DIHUBUNGI, BARANG_RUSAK, JALAN_TERPUTUS, LAINNYA).
   - Pengambilan foto fisik via kamera (`image_picker`) + kompresi + preview.
   - Kanvas tanda tangan digital interaktif (`signature`).
   - Multipart file upload ke `POST /v1/files/upload` dan submit ke `POST /v1/me/stops/:id/pod` dengan header `Idempotency-Key`.
2. FASE 2: Visualisasi Rute Peta (Polyline) & Navigasi Eksternal
   - Fetching geometri rute dari `GET /v1/deliveries/:id/routes/current`.
   - Rendering PolylineLayer pada `ArmadaOsmMap` (OpenStreetMap).
   - Penomoran marker stop (1, 2, 3...) dengan status visual.
   - Tombol navigasi luar (`url_launcher`) memicu Google Maps/Waze ke koordinat stop.
   - UI rekomendasi dan pemilihan rute terbaik (`POST /v1/deliveries/:id/routes/recommend` & `select`).
3. FASE 3: Manajemen Pengiriman & Penugasan Armada oleh Owner
   - Form pembuatan order baru: nomor DO, multi-stop builder (nama toko, alamat, koordinat), cargo item builder (nama barang, koli, berat kg).
   - Modal penugasan driver & armada kendaraan (`POST /v1/deliveries/:id/assign`) dengan validasi kapasitas muatan.
   - Detail pengiriman komprehensif & riwayat audit log aktivitas.
4. FASE 4: Realtime Gateway (Socket.IO) & In-App Notification Center
   - Integrasi client `socket_io_client` ke `wss://<host>/v1/realtime` dengan autentikasi Bearer handshake.
   - Event streaming: `driver:location:update`, `delivery:status:changed`, `emergency:triggered` untuk pembaruan marker real-time tanpa polling REST.
   - Pusat notifikasi (`GET /v1/notifications`, `PATCH /v1/notifications/:id/read`).
   - Notifikasi darurat SOS banner dan sound alert.
